01 — The problem

Solr's query syntax is the barrier, not Solr

To ask a straightforward question you first have to know this:

q=title:"star wars" AND genre_s:"sci-fi"&fq=year_i:[2000 TO *]
&facet=true&facet.field=genre_s&sort=score desc&rows=10

Every parameter is learnable. All of them at once, while you are trying to answer a question, is where people give up.

02 — What MCP changes

You describe the question. The assistant writes the query.

“Find sci-fi shows released after 2015 rated 8 or above, sorted by rating, with a platform breakdown.”

The assistant produces the parameters above because the tool descriptions told it how. That translation layer is the entire product — the server exposes Solr operations as MCP tools, and any MCP client can call them.

  • 11 tools — search, index (JSON/CSV/XML), collections, schema
  • 2 resources — live collection list, live schema
  • 6 prompts — guided workflows your client may surface as slash commands

03 — Ten minutes, start to query

No clone, no build

# 1. Solr — SolrCloud in one container
docker run -d --name solr-mcp-demo -p 8983:8983 \
  solr:9-slim solr start -c -f

# 2. The server — Claude Code shown; every client is on the card
claude mcp add solr-mcp -- docker run -i --rm \
  --add-host=host.docker.internal:host-gateway \
  -e SOLR_URL=http://host.docker.internal:8983/solr/ \
  ghcr.io/adityamparikh/solr-mcp:coc2026

Then talk to it. Claude Desktop, Claude Code, VS Code / Copilot, Cursor, Zed, IntelliJ, or MCP Inspector — the card has the exact block for each.

04 — The interesting part

Why field types decide what you can ask

Index 61 shows with no schema at all. It works — every document lands. Then ask for a breakdown by platform:

{ "numFound": 61, "facets": { "platform": {} } }

Sixty-one matched. The query succeeded. There is simply no answer — and nothing tells you the data is fine and the field type is the problem.

05 — Beyond search

Ask about the index itself

“Is the shows collection healthy?”

“What's my query result cache hit ratio, and what does that tell me?”

“Which fields can I facet on, and which can I sort by?”

That last one is the one to try. The assistant has the schema and knows Solr's type semantics, so it answers a question that would otherwise mean reading managed-schema and knowing what docValues implies.
